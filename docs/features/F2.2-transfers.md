# F2.2 — Transfers between classes

**Status:** ✅ Built · ✅ Deployed · ✅ Unit tested · ✅ End-to-end checked (2026-10-05)

## What it does

`TransferService.transfer` moves an active enrolment to another class in one transaction:

| Step                         | Rule                                                                                                                                                                                                                                                  |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Checks                       | Active enrolment; a different class; no discount awaiting approval; transfer date not before the enrolment started; the target class's normal enrolment rules (open, seat free — held waitlist seats count as taken — learner not already there)      |
| New enrolment                | Enrolled in the target class at the **current price list** with the **same discount code**; start date = transfer date; linked back (`Transferred_From__c`); application carried over                                                                 |
| Old enrolment                | Ends as **Withdrew** on the transfer date with reason "Transferred to ‹class›: ‹reason›" and a forward link (`Transferred_To__c`); its seat is released and **offered to that class's waitlist** (F2.1); attendance and results stay on it as history |
| Not yet invoiced             | The old uninvoiced fee lines are dropped; the new enrolment is billed at its own price                                                                                                                                                                |
| Already invoiced, price up   | The new enrolment gets **one adjustment fee line** for the difference only (invoice it as usual)                                                                                                                                                      |
| Already invoiced, same price | Nothing more to bill; the billing status (e.g. Paid) is carried over                                                                                                                                                                                  |
| Already invoiced, price down | The difference is recorded as **Credit_Due__c** on the new enrolment, to be settled by a credit note or refund (F2.4)                                                                                                                                 |
| Audit                        | `Transfer_Adjustment__c` keeps new − old agreed total                                                                                                                                                                                                 |

## User interface

Class roster ▾ → **Transfer to another class** opens `kemTransferModal`: open classes of the branch with free seats, transfer date, reason, and a live preview — current vs new price, the difference (amber for more, green for less), what happens to billing, and any blocker. The roster and the waitlist panel refresh after the transfer.
