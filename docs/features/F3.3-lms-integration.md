# F3.3 — Generic LMS integration API

**Status:** ✅ Built · ✅ Deployed · ✅ Unit tested · ✅ End-to-end checked (2026-10-06)

No LMS has been chosen yet, so the integration is a generic, documented contract any LMS (Moodle, Canvas, Google Classroom through middleware, …) can use: **classes and rosters out, grades in, changes as events**.

## Integration user

Create an API-only user and assign the permission set group **KEM Integration Persona** (`KEM_Integration` + `KEM_Integration_Edu`): read access to classes, enrolments, learners (View All), courses and branches; create/edit on assessments and results; the **KEM Integration** and **KEM Manage Billing** custom permissions; the API classes. Connect with OAuth (Connected App, client credentials). Never share its credentials in chat or tickets.

## Endpoints (`/services/apexrest/kem/v1/lms/...`)

| Method | Path                                     | Purpose                                                                                                                    |
| ------ | ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| GET    | `classes?branch=&status=&modifiedSince=` | Classes (id, name, course and course code, branch code, status, dates, capacity, delivery mode, teacher email), max 2,000  |
| GET    | `classes/{id}`                           | One class                                                                                                                  |
| GET    | `classes/{id}/roster`                    | Enrolments of the class: learner id, names, email, status                                                                  |
| POST   | `grades`                                 | Create or update an assessment by the LMS's `externalId` with results by `learnerId` or `learnerEmail`; optional `publish` |
| GET    | `events?after=EVT-…&limit=`              | Pending LMS events after the cursor (oldest first, up to 1,000), with `next` and `hasMore`                                 |
| POST   | `events/ack`                             | `{ "events": ["EVT-…"], "success": true }`, or `false` with `error`: marks events Delivered or Failed                      |

Responses are JSON; errors are `{ "error": "…" }` with 400 (invalid request), 403 (no KEM Integration permission), 404 (unknown class or resource), 500 (unexpected, with a request reference; logged).

**Grades** go through the gradebook rules (`AssessmentService`): scores between 0 and the maximum, absent flags, grades fixed at publication, published results locked (a re-send after publication is refused). The whole request is all-or-nothing; learners not enrolled in the class are listed in the error. The assessment keeps `External_Id__c`, so re-sending the same grades updates instead of duplicating (201 created, 200 updated).

## Outbox (`Integration_Event__c`, EVT-00000001)

`IntegrationService` records a JSON snapshot when something an external system cares about changes:

| Target | Event                                                                                           | When                                                                                      |
| ------ | ----------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| LMS    | `class.updated`                                                                                 | Class created, or name, status, dates, capacity, teacher, delivery mode or course changed |
| LMS    | `enrolment.updated`                                                                             | Enrolment created, or its status or class changed                                         |
| LMS    | `grades.finalised`                                                                              | Course grades finalised (F2.7), with every learner's score and grade                      |
| ERP    | `invoice.issued`, `invoice.cancelled`, `payment.confirmed`, `credit_note.issued`, `refund.paid` | Finance documents (F3.4)                                                                  |

- One event per record and type per transaction; recording never breaks the business action (errors are logged).
- Settings: `LMS_Outbox` / `ERP_Outbox` (On), `LMS_Push` / `ERP_Push` (Off), `Integration_Retention_Days` (30).
- **Push (optional):** with `<TARGET>_Push` On, the hourly **KEM Integration Sync** job POSTs up to 50 pending events to the named credential `KEM_LMS` / `KEM_ERP` at `/events`; a 2xx response marks them Delivered, otherwise they are Failed and retried (up to 5 attempts). The named credential is created by an administrator when the LMS is chosen.
- **Housekeeping:** the same job deletes delivered events after 30 days and any event after 90, and expires payment links (F3.7).
- **Operations console:** queues "Integration events failed" and "Integration events waiting over a day".

## Tests

- Apex `LmsIntegrationTest`: outbox records class and enrolment changes (and only relevant changes), switch-off; classes with branch filter, detail, roster with learner emails, 404/400 handling; event paging and acknowledgement (Delivered / Failed with error and attempts); grades created as draft (201), updated and published (200), locked afterwards (400); validation (malformed JSON, unknown learner named, missing external ID, unknown resource) with nothing saved; non-integration users refused (403); push failure then delivery; purge rules.
