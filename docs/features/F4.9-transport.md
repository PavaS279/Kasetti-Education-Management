# F4.9 — Transport: routes, stops, riders and transport fees

**Status:** ✅ Built · ✅ Deployed · ✅ Unit tested · ✅ End-to-end checked (2026-10-06)

## Set-up

| Object                               | What it holds                                                                                                                                                                                         |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Transport Route**                  | Branch, route code (unique, e.g. `BLR-R1`), vehicle, driver and phone, attendant, seats, **monthly fee**, morning and afternoon start, active                                                         |
| **Transport Stop**                   | Belongs to a route: order, pick-up time, drop time, landmark, active                                                                                                                                  |
| **Transport Assignment** (TR-000001) | A learner riding a route from a stop: direction (Both ways, Morning only, Afternoon only), start and end dates, status (Active, Ended), monthly fee, the fee line and the enrolment it is billed with |

Administrators and branch managers create routes (**New route**) and their stops (**Add stop**) on the desk. Seats taken are counted by the system.

## Transport desk (`kemTransportDesk`)

On each **Branch** page (the org has reached its limit of custom tabs, so there is no separate tab):

- Route cards with seats used (red when full), fee, code, vehicle and driver.
- The selected route's **manifest**: stops in order with times and landmark, the riders at each stop with direction and the fee payer's name and phone. **Print** prints the manifest only.
- **Add learner**: search learners enrolled at the route's branch (their current route is shown), choose stop, direction and start date, and whether to charge the fee.
- Per rider: change the stop, or end the transport (from today).
- **Message families**: a message to the fee payer of every rider (for example a delay), through the messaging rules (portal; email when delivery is on). Template `Transport_Notice`.

## Rules

- A learner rides one route at a time; a full route refuses more riders (the route is locked while a seat is taken); the start date cannot be in the past.
- **Transport fee:** a monthly fee line of type **Transport** is added to the learner's active class enrolment at the route's branch (the one ending last). Recurring billing invoices it from the **start date** with the learner's other fees (the nightly job bills transport lines from their start, without waiting for a first manual invoice), at 0% tax.
- **Ending:** the line gets a **Bill Until** date; months starting after it are not billed and the line closes. Ending before the start date bills nothing. (Bill Until is a new field on fee lines, honoured by `BillingService` for any monthly line.)
- Without an active enrolment at the branch the fee cannot be billed: the desk says so; staff can assign without a fee (free transport).
- Families see the route, stop, pick-up and drop times, vehicle and driver on the **Transport** tab of the portal.

## Access

| Who                                      | Can                                                          |
| ---------------------------------------- | ------------------------------------------------------------ |
| Administrators, branch managers          | Manage routes and stops, assign, end, message                |
| Admissions counsellors                   | Assign and end riders, message families                      |
| Academic coordinators, teachers, finance | Read routes and the manifest (finance reads all assignments) |
