# F1.5 — Enrolment with seat control and agreed price

**Status:** ✅ Built · ✅ Deployed · ✅ Unit tested · ✅ End-to-end checked (2026-10-03)

## What it does

| Capability             | How                                                                                                                                                                                                                          |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Class (offering) setup | `CourseOffering` + `Branch__c`, `Room__c`, `Delivery_Mode__c`, `Class_Status__c` (Planned → Open ↔ Full → In Progress → Completed / Cancelled, governed), `Teacher_User__c`, `Seats_Taken__c`, `Seats_Available__c`          |
| Enrolment              | Native `CourseOfferingParticipant` (Student, Enrolled) created by `EnrolmentService.enrol`                                                                                                                                   |
| Seat control           | Class row locked (`FOR UPDATE`) during enrolment; active seats (Enrolled, On Hold) counted; full classes reject enrolment; `SeatService` recounts on every insert, status change, and delete and moves the class Open ↔ Full |
| Agreed price           | Quote from `PricingService` (class course, branch, delivery mode, today, optional discount) copied to `Agreed_*` fields and immutable `Enrolment_Fee_Line__c` rows. Later price-list changes never alter an enrolment        |
| Guards                 | Learner role required, no duplicate active enrolment, class must be Open/In Progress, course must be priced, discount code must be valid, application (if given) must belong to the learner with an **accepted** offer       |
| Application link       | Enrolling from an application marks it **Enrolled**                                                                                                                                                                          |
| Discount approval      | Approval-required discounts → `Discount_Approval_Status__c = Pending`; users with **KEM Approve Discounts** (finance, admin) approve, or reject which re-prices the enrolment without the discount (only before invoicing)   |
| Withdrawal             | Reason required; effective date (clamped to start date); status Withdrew; seat released and class reopened                                                                                                                   |

## User interface

- **`kemEnrolModal`** — 3-step wizard (learner search → class picker with seat bars → agreed-price review with discount code and blockers → confirm). Launched from the class roster, the application workbench (_Enrol in class_ once the offer is accepted, pre-filled with course, branch, preferred class, and application), and Learner 360 (_Enrol in class_).
- **Class record page** (`KEM_Class_Record_Page`) with **`kemClassRoster`**: hero with class facts and animated seat meter, roster table with status, agreed total, discount and approval, billing status, and per-row actions (withdraw, approve/reject discount, open).

## Tests

- Apex `EnrolmentServiceTest` (8 tests): snapshot and seat control to Full, preview blockers, snapshot immutability after price change, six invalid-enrolment cases, application-driven enrolment, discount approval/rejection with re-pricing and usage counting (finance vs counsellor), withdrawal releasing the seat and reopening the class, invalid class transition, roster/lookups, counsellor end to end.
- Jest: `kemClassRoster` (seat meter, roster, discount actions), `kemEnrolModal` (class step, seat label, preview call).
