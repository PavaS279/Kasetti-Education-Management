# F2.3 — Recurring billing and instalment plans

**Status:** ✅ Built · ⬜ Deployed · ⬜ Unit tested · ⬜ End-to-end checked

## Recurring monthly billing

Fee prices with **Billing Frequency = Monthly** become recurring fee lines on the enrolment. One-time and term lines are still billed once.

| Rule                 | Behaviour                                                                                                                                                                                                                   |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| First invoice        | Raised by staff as before (Enrolment → Create invoice). It bills one-time/term lines plus the **first monthly period** (from the enrolment start date), and catches up any later periods that have already started          |
| Billing periods      | Calendar months from the enrolment start date: e.g. start 28 Sep → periods 28 Sep–27 Oct, 28 Oct–27 Nov… The last period ends with the enrolment                                                                            |
| Invoice lines        | Each period is its own line with `Period_Start__c`/`Period_End__c` and the period in the description, e.g. "Tuition (Oct 2026)"; the invoice gets `Billing_Period__c` ("Oct 2026" or "Oct 2026 - Dec 2026")                 |
| Fee line tracking    | `Next_Bill_Date__c` (start of the next period) and `Periods_Billed__c`; the line is marked **Invoiced** only once the next period would start after the enrolment end date                                                  |
| Nightly job          | **KEM Recurring Billing** (02:10 daily, `RecurringBillingJob`) raises and issues an invoice for each **Enrolled** enrolment on recurring billing whose next period has started (at most 12 periods of catch-up per invoice) |
| Isolation            | Each enrolment is billed in its own savepoint; a failure is written to the error log and the rest continue; the run summary is logged                                                                                       |
| Not due yet          | Creating an invoice when nothing is due says when the next period is billed                                                                                                                                                 |
| Cancelling           | Cancelling an invoice steps the monthly line back to the first cancelled period (and releases the schedule completely if no period remains billed); its instalment plan is deleted                                          |
| Out of scope (later) | Proration of part months, pausing billing for On Hold enrolments (On Hold enrolments are skipped by the job)                                                                                                                |

## Instalment plans

An issued invoice can be split into **2–12 instalments**, monthly or every 2, 3 or 6 months (`Instalment__c`, master-detail to the invoice).

| Rule     | Behaviour                                                                                                                                                        |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Split    | Equal amounts rounded down to the paisa; the remainder goes on the last instalment                                                                               |
| Payments | Still allocated to the invoice as a whole (F1.9 unchanged); the paid amount settles instalments **in order** (Due → Partially Paid → Paid)                       |
| Due date | The invoice due date follows the **first unpaid instalment**, so the Overdue flag, Finance Desk and reminders work per instalment; the original due date is kept |
| Guards   | Only Issued / Partially Paid invoices; one plan per invoice; first due date not before the invoice date; KEM_Manage_Billing required                             |
| Removing | Restores the original due date; payments stay allocated                                                                                                          |

## User interface

Invoice page (`kemInvoice`):

- **Pay in instalments** opens `kemInstalmentModal`: number of instalments, first due date (defaults to the invoice due date) and frequency, with a live schedule preview.
- **Instalments** panel: each instalment with due date, amount, paid bar and status (Overdue in red), "n of m paid" and the original due date; **Remove plan**.
- The hero shows the billing period; monthly lines show their period dates.
