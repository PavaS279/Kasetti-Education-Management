# F3.7 — Online payments in the portal

**Status:** ✅ Built · ✅ Deployed · ✅ Unit tested · ✅ End-to-end checked (2026-10-06) — **switched Off** until a gateway is connected

Gateway-agnostic: Salesforce creates a **payment link**; the gateway (Razorpay, PayU, Stripe, … or middleware in front of it) takes the money and confirms through a **signed webhook**. The payment is then recorded exactly like other gateway payments (F1.9): allocated, reconciled, receipt and notices.

## Modes (Education Setting `Payment_Gateway_Mode`)

| Mode               | Family portal                                                                                                                        | Staff (invoice page → Online payment)                                                                 |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| **Off** (this org) | No Pay online button                                                                                                                 | "Families pay at the branch"                                                                          |
| Test               | **Pay online** creates a link; "Test mode: no money is taken"                                                                        | Links listed; **Simulate payment** records the payment                                                |
| Live               | **Pay online** opens the gateway checkout (`Payment_Checkout_URL` with `{token}`, `{amount}`, `{invoice}`, `{currency}`; HTTPS only) | **Create payment link** shows the checkout address to share; warning if the webhook secret is missing |

## Payment links (`Payment_Link__c`, PL-000001)

Invoice, payer, branch, amount (the balance due), random 48-character token, status (Active, Paid, Expired, Cancelled, Failed), expiry (`Payment_Link_Hours`, 24), checkout URL, resulting payment, gateway reference, created via (Portal / Staff). An active link for the same balance is reused. Families can only start payments for learners they may see in the portal. The hourly **KEM Integration Sync** job expires old links.

## Webhook

`POST /services/apexrest/kem/v1/payments/webhook` (integration user), header `X-KEM-Signature` = hex HMAC-SHA256 of the raw body with the shared secret, body `{ "token", "transactionId", "amount", "status": "success" | "failed" }`.

- 503 until the secret is set; 401 for a missing or wrong signature (logged); 400 for an unknown link, missing transaction, an amount above the link or an invalid status.
- Success records an **Online Gateway** payment with the gateway transaction ID (idempotent: a repeat returns `duplicate: true`) and marks the link Paid; a late confirmation of an expired link is still recorded (the money was taken). `failed` marks the link Failed.
- The secret lives in the custom setting **KEM Gateway → Webhook Secret** (Setup → Custom Settings → KEM Gateway → Manage). No permission set grants access to it; only administrators (View All Custom Settings) can read it. Enter it in Setup only, never in chat or tickets.

## Tests

- Apex `PaymentLinkTest`: Off by default; Test mode link creation and reuse, no token or checkout; other families refused; Live checkout address (HTTPS only); signed webhook: bad signature 401, payment recorded and invoice Paid, repeat duplicate (signature case-insensitive); 503 without secret, unknown link, missing transaction; amount above the link, failed payment; Test-mode simulation, nothing left to pay, no simulation in Live; link expiry.
- Jest: `kemPortalHome` (Pay online in Test and Live, unavailable message) and `kemPaymentLinks` (off, test simulation and creation, live warning and checkout address, hidden).
