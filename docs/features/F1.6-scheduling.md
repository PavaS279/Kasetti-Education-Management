# F1.6 — Scheduling: sessions, conflicts, timetable

**Status:** ✅ Built · ✅ Deployed · ✅ Unit tested · ✅ End-to-end checked (2026-10-03)

## What it does

| Capability         | How                                                                                                                                                                                                                                                                                                                     |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Weekly patterns    | Native `CourseOfferingSchedule` per class (days, start/end time, start date, type) — added from the class page (_Add weekly pattern_)                                                                                                                                                                                   |
| Session generation | `SessionService.generate`: one `Class_Session__c` per matching day from the pattern start (or class start) to the class end, capped by `Session_Horizon_Days`; inherits room, teacher, branch, mode; **idempotent** via `External_Id__c` = class + start; skips `Calendar_Closure__c` dates (branch-specific or global) |
| Conflict detection | `ClassSessionTriggerHandler` rejects teacher or room double-booking on insert and on any time/room/teacher/status change (including clashes within the same batch). Back-to-back sessions are allowed. Learner clashes (learners enrolled in another class at the same time) are reported as **warnings**               |
| Rescheduling       | Keeps `Original_Start__c` (first original only), sets `Rescheduled__c`, records the reason; blocked for cancelled sessions                                                                                                                                                                                              |
| Cancellation       | Reason required (validation rule + service); status governed (Scheduled ↔ Cancelled/Completed)                                                                                                                                                                                                                          |
| Ad-hoc sessions    | Extra / make-up / exam sessions from the class                                                                                                                                                                                                                                                                          |
| Visual calendar    | **Timetable** tab                                                                                                                                                                                                                                                                                                       |

## User interface

- **Timetable** tab (`kemTimetable`): week grid 07:00–21:00, colour per class, today marker and live _now_ line, week navigation, branch/teacher (_My sessions_)/room filters, **drag-and-drop** to another day/time (15-minute snap) with server-side conflict preview — teacher/room clashes are refused with the reason, learner clashes ask for confirmation — session drawer with details, _Open class_, _Cancel session_. Cancelled sessions are hatched and not draggable. On phones it switches to a single-day view with day pills.
- Class page (`kemClassRoster`) scheduling menu: _Add weekly pattern_ (`kemPatternModal`), _Generate sessions_ (summary toast with created / existing / closures / conflicts), _Open timetable_.
- Tabs: Timetable, Class Sessions, Calendar Closures.

## Known limitation

`CourseOfferingSchedule.EndDate` cannot be granted to the persona permission sets in this org (the platform rejects writes even with field permission). Patterns therefore run until the **class end date**; set the class end date to bound a pattern.

## Tests
