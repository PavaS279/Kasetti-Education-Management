# F2.1 — Waitlists

**Status:** ✅ Built · ✅ Deployed · ✅ Unit tested · ✅ End-to-end checked (2026-10-05)

## What it does

| Capability  | How                                                                                                                                                                                                                                                                                                      |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Join        | `Waitlist_Entry__c` for a learner in a **full** class (refused when seats are free and nobody is waiting, when already enrolled, or already queued). Priority (Normal / Priority / Urgent), discount code to apply at enrolment, notes, optional application                                             |
| Queue order | Highest priority first, then first come, first served                                                                                                                                                                                                                                                    |
| Seat offers | Whenever a seat is freed — withdrawal, capacity increase, an offer declined, expired or removed — the seat is **offered and held** for the next learner (`Status` Offered, `Offer_Expires__c` = now + `Waitlist_Offer_Hours`, default 48). A high-priority follow-up task is created for the entry owner |
| Held seats  | `CourseOffering.Seats_Reserved__c`; Seats Available = capacity − taken − held; the class stays **Full** while a seat is held, and nobody else can enrol into it                                                                                                                                          |
| Answers     | **Accept seat** enrols the learner into the held seat at today's price (with the waitlist discount code; linked to the application if its offer was accepted). **Declined** / **Remove** pass the seat on. **Back in queue** returns an expired or declined learner to their original place              |
| Expiry      | Hourly job **KEM Waitlist Offers** (`WaitlistOfferJob`) expires unanswered offers and offers the seats onward                                                                                                                                                                                            |
| Counters    | `CourseOffering.Waitlist_Count__c` (learners waiting) kept with seat counts in `SeatService`                                                                                                                                                                                                             |
| Governance  | Status transitions in `Status_Transition__mdt`; all waitlist fields are system-managed and changed only through `WaitlistService` (object create access required: administrators, branch managers, counsellors, academic coordinators)                                                                   |

## User interface

**Class page → Waitlist** (`kemWaitlist`): seat strip (capacity, taken, held for offers, free, waiting); queue with position, priority badge, status and a live **reply-within** countdown for held seats; **Accept seat** / **Declined** / remove; collapsible history with **Back in queue** and a link to the resulting enrolment; **Add to waitlist** opens `kemWaitlistJoinModal` (learner search, priority, discount code, notes). Waitlist and roster on the same page refresh each other through the `KEM_Class_Changed` message channel.

## Tests

- Apex `WaitlistServiceTest`: priority order and positions; withdrawal offers and holds the seat (class stays Full, others refused, task created); accept enrols and releases the hold; capacity increase offers; decline passes the seat on; expired offers cannot be accepted and the job expires them and offers onward; requeue and removal; join guards (duplicate, already enrolled, seats free); teacher refused; controller error handling.
- Jest `kemWaitlist` (seats, countdown, queue, history, accept + refresh message, join form) and `kemWaitlistJoinModal` (search, pick, priority, join).

## Data model

`Waitlist_Entry__c` (WL-number, Read sharing, history, activities): Course_Offering, Learner (account) + Learner_Contact, Application, Branch, Status (Waiting/Offered/Enrolled/Declined/Expired/Cancelled), Priority, Requested_On, Offered_On, Offer_Expires, Responded_On, Discount_Code, Enrolment, Offers_Made, Notes. `CourseOffering`: Seats_Reserved__c, Waitlist_Count__c; Seats_Available__c now subtracts held seats.
