# F5.7 — Fixing set-up gaps where they are found

**Status:** ✅ Built · ✅ Deployed · ✅ Unit tested · ✅ Checked in the org (2026-10-07)

**Why:**

- Reported on 7 Oct: the Set-up Centre listed **Classes without a teacher**, but opening a class gave no way to add a teacher or faculty.
- **First cause:** the record pages show each object's page layout. The org's layouts were created with the objects, and fields deployed afterwards are never added to existing layouts. The Class layout therefore had no Teacher (User), Room, Branch, Delivery or Class Status. The same applied to almost every KTEdutech object; the Branch layout, for example, had only the code and name, and no related lists.
- **Second cause:** sessions copy the class's teacher and room when they are generated. Changing the class's teacher afterwards did not change its upcoming sessions, so registers, cover and My sessions would still have no teacher.

## Class set-up (`kemClassSetup`, `kemClassSetupModal`)

A **Class set-up** card sits at the top of the class page's right-hand column.

**It shows:**

- Teacher (login), faculty, branch, room, seats taken / seat limit, and upcoming sessions.
- What is missing, with the reason:
  - no teacher login (registers, marks, cover);
  - no faculty (timetable, report cards);
  - no room;
  - no seat limit;
  - no weekly times ("class menu → Add weekly pattern, then Generate sessions");
  - upcoming sessions without a teacher.
- "Fully set up" when nothing is missing.

**Edit** opens the form:

- Branch.
- Delivery.
- **Teacher (login):** the branch's teachers first, then other staff at the branch with their role. A note says when no one has the Teacher role there.
- **Faculty shown to families.**
- **Room:** with seats; a room smaller than the class is stopped.
- Seats: at least the number already enrolled.
- Status.

**Saving:**

- A new teacher or room is also set on the class's upcoming scheduled sessions.
- Sessions being covered keep their cover teacher.
- A session that would clash keeps its old value and is listed ("Saved. 9 upcoming sessions updated; these kept their old teacher or room because of a clash: …").
- The page's details refresh.

The same card opens as a pop-up from the Set-up Centre: clicking a class under **Classes without a teacher / a branch / a room / a seat limit** fixes it in place.

## Sessions follow the class

`ClassSetupService.propagate`, called from the class trigger, applies the same rules to edits made in the standard form. A clash keeps the old value and is written to the error log as a warning.

## Set-up Centre gaps

Each gap now says exactly where to fix it, and the links do the right thing:

| Gap                                                   | Click                                                          |
| ----------------------------------------------------- | -------------------------------------------------------------- |
| Classes without a teacher, branch, room or seat limit | Class set-up pop-up                                            |
| Branches without rooms                                | Add rooms, for that branch                                     |
| Branches without a manager                            | The branch: Edit → Branch Manager                              |
| Courses without a tuition price                       | The course: Course pricing                                     |
| Running classes with no upcoming sessions             | The class: class menu → Add weekly pattern → Generate sessions |

  - Class: Teacher (User), Room, Branch, Delivery, Class Status, seats, grading.

## Access

`ClassSetupController` is in the KEM Administrator, Branch Manager and Academic Coordinator permission sets. Teachers see the card read-only, or not at all without access. Saving uses the person's edit access to classes. Sessions are updated in system mode, only as a consequence of that class change.
