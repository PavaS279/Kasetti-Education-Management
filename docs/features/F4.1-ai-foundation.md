# F4.1 — AI foundation: Einstein, governance, review and measurement

**Status:** ✅ Built · ✅ Deployed · ✅ Unit tested · ✅ End-to-end checked (2026-10-06)

Every AI feature in Kasetti Education Management goes through one service (`AiService`) so that access, logging, review and measurement are the same everywhere. Principles: see [AI opportunities](../ai/AI-OPPORTUNITIES.md) (human in the loop, controlled access, grounded in live data, measured, minimal data).

## How a request works

1. A panel (or an Agentforce action) asks an assistant for a draft: `AiAssistantService` gathers the facts from the record **as the user** (sharing and field access apply).
2. `AiService.generate` takes the prompt from the catalogue (`AI_Prompt__mdt`: versioned instructions, template, word limit, model, minutes saved per use), fills it in and calls **Einstein** (Models API, `aiplatform.ModelsAPI.createChatGenerations`). The call goes through the **Einstein Trust Layer** (data masking, zero data retention at the model provider, audit).
3. The answer is cleaned (Markdown emphasis and headings removed: drafts are used as plain text) and logged as an **AI Interaction** (`AI_Interaction__c`).
4. The draft is shown to staff, who use it as is, edit it, or discard it. **Nothing is sent or saved by the AI.** The outcome is written back to the interaction.

## Controls

| Control            | Where                                                                                        | Effect                                                                           |
| ------------------ | -------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| Kill switch        | Education Setting `AI_Enabled` (On/Off)                                                      | Off hides every AI panel and refuses every AI call                               |
| Per-feature switch | Education Setting `AI_Disabled_Features` (comma list)                                        | For example `Enquiry Reply, Document Extraction`                                 |
| Who may use AI     | Permission set **KEM AI User** (custom permission `KEM_Use_AI`)                              | Panels are hidden and calls refused without it; assign per person                |
| Model              | Education Setting `AI_Model` (default `sfdc_ai__DefaultGPT4Omni`); a prompt can name its own | Any Einstein model enabled in the org                                            |
| Prompt changes     | `AI_Prompt__mdt` records (deployed, versioned)                                               | The version used is stored on each interaction; evaluation re-run after a change |

## Measurement

`AI_Interaction__c` (private; staff see their own, administrators all) records feature, prompt and version, model, **channel** (In-app, Agentforce, Evaluation), record, branch, status (Succeeded/Failed/Blocked), latency, input and output size, the response, and the review:

| Outcome        | Meaning                                                                                       |
| -------------- | --------------------------------------------------------------------------------------------- |
| Pending Review | Draft shown, not yet used or discarded                                                        |
| Accepted       | Used without changes (edit ratio 0)                                                           |
| Edited         | Used after changes; **edit ratio** = share of words changed (word-level edit distance, 0–100) |
| Rejected       | Discarded, or marked not helpful                                                              |
| Not Applicable | Failed calls, Agentforce and evaluation calls (shown directly, no review step)                |

**Minutes saved (estimate)** = the prompt's minutes per use × (1 − edit ratio). Staff can add a 1–5 rating and a comment.

## AI console (`kemAiConsole`, Home page)

For the last 7/30/90 days: AI requests, staff using AI, Agentforce actions, share of drafts used (as is or edited), minutes saved, average response time and failed requests; a table per feature (requests, used, edited, rejected, average edit, rating, minutes); the latest evaluation; and the current switches and model. Administrators see everyone's figures and can run the evaluation; other AI users see their own. Evaluation runs are not counted as use.

## Evaluation (`AiEvaluationService`)

Test cases (`AI_Eval_Case__mdt`) give a prompt fixed inputs and check the answer: phrases it must contain, phrases it must not contain (for example invented prices, or values injected into a document), the word limit (+20%) and valid JSON where expected. **Run evaluation** (administrators) runs every case against the live model, stores each result (`AI_Evaluation__c`: run, case, prompt version, model, passed, score, checks, latency) and shows the summary. Run it after any prompt or model change.

10 cases: enquiry reply grounded and without invented prices, progress summary tone, report comment length, refund policy limit, unknown policy refused, record summary bullets, document extraction (birth certificate, report card, injected instructions ignored).

## Objects and metadata

- `AI_Prompt__mdt`, `AI_Eval_Case__mdt`, `AI_Knowledge__mdt` (custom metadata types).
- `AI_Interaction__c`, `AI_Evaluation__c` (private; written only by the system).
- Custom permission `KEM_Use_AI`, permission set `KEM_AI_User` (read own interactions, AI Apex classes).
- Classes: `AiService`, `AiAssistantService`, `AiKnowledge`, `AiJson`, `AiEvaluationService`, `AiConsoleService`, `AiController`, `AiExtractionService`, `Agent*`.
