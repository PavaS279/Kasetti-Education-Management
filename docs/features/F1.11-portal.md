# F1.11 — Basic learner and guardian portal

**Status:** ✅ Built · ✅ Deployed · ✅ Unit tested (with a real portal user) · ✅ End-to-end checked (2026-10-03) · ✅ Live on `TrialOrgPortal` → **My Learning** (`/my-learning`)

## What it does

| Capability              | How                                                                                                                                                                                                                                                                                                              |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Who sees what (ADR-003) | `PortalService.authorisedLearners`: the signed-in contact (if a learner) plus learners linked by an **active** guardian relationship with **Portal Access** ticked. Every learner ID from the browser is checked against this set                                                                                |
| Data                    | Home: family greeting, per-learner cards (student number, active classes, average attendance, balance due, overdue count, next class). Learner view: classes, sessions for the next 14 days (room or join link; cancelled sessions flagged), recent attendance, **published** results only, issued/paid invoices |
| Security                | Portal users hold no object permissions; `PortalService` reads without sharing but only within the authorised set and returns DTOs (no records), so no other field can reach the browser. `KEM_Portal_User` grants only `PortalController` (licence `EducationCloudExprcCloudAccessPsl`)                         |
| Internal users          | Get a clear message (“This page is for learners and guardians signed in to the portal.”)                                                                                                                                                                                                                         |

## User interface — `kemPortalHome` (“KEM Learner & Guardian Home”)

Mobile-first: gradient hero with a time-of-day greeting and learner switcher chips (guardians with several children), summary tiles (attendance — red below 75%, active classes, next class, balance due with overdue state), segmented control **Timetable · Results · Attendance · Fees**: day-grouped sessions (Today/Tomorrow) with **Join** buttons for online classes, grade bubbles with score and teacher feedback, colour-coded attendance marks (late minutes), invoices with balance and status (overdue highlighted). Two-column tiles on phones.

### Placing it on the site (one-time, about two minutes)

The site `TrialOrgPortal` is live and its content is not retrievable through the Metadata API in this org (ExperienceBundle metadata is disabled), so the component was not deployed into the site automatically to avoid overwriting live site configuration.

1. Setup → Digital Experiences → All Sites → **TrialOrgPortal** → Builder.
2. Open the Home page (or create a page, for example _My Learning_), drag **KEM Learner & Guardian Home** from Custom Components onto it.
3. Publish.
4. Give portal users the **KEM Portal User** permission set (with the Education Cloud experience licence) and tick **Portal Access** on their guardian relationship (Learner 360 → Guardians).
