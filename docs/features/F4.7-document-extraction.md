# F4.7 — AI document reader for applications

**Status:** ✅ Built · ✅ Deployed · ✅ Unit tested · ✅ End-to-end checked (2026-10-06, service and PDF text; panel not yet browser-checked)

On the **application page**, the _AI document reader_ (`kemAiDocumentReader`) reads an admission document and proposes details for the learner, the guardian and their previous school, next to what is already on record. Staff tick what is right, correct values if needed and press **Apply**. Nothing is saved before that.

## Documents

| Source        | How it is read                                                                                                                           |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Attached      | Files on the application or its checklist items (up to 4 MB). PDFs are read in the browser with pdf.js; text and CSV files on the server |
| From computer | A PDF or text file chosen by staff, read in the browser and **not stored**                                                               |
| Paste text    | Text copied from an email or form                                                                                                        |

Only the **text layer** is read: a scanned image or photo has none (no OCR licence), and the panel says so and suggests typing the details. pdf.js 3.11.174 (Apache-2.0) is the static resource `pdfjs`, loaded only by this panel, with script evaluation, font loading and extra fetches switched off. At most 15 pages and 12,000 characters are read.

## What is extracted

Einstein (prompt `Document_Extraction`, through the Trust Layer) returns JSON with: document type; learner first and last name, date of birth, email, mobile, street, city, postal code; guardian first and last name, relationship, phone, email; previous school and grade. The prompt forbids guessing and **excludes health, religion, caste, income and identity numbers**, and treats the document as data (instructions written inside it are ignored; an evaluation case checks this). Dates are read day first and converted to YYYY-MM-DD; emails are lower-cased and phone numbers reduced to digits.

## Proposals and rules

- Values that **fill a blank** are ticked by default; values that **differ** from the record are not ticked ("Differs from the record: tick to replace"); values that match are shown for confirmation.
- **No guardian linked:** ticking the guardian's last name adds them (fee payer and emergency contact) through the normal guardian service, reusing an existing person when one matches.
- **Guardian linked:** names and relationship are never changed from a document. Phone and email can be updated only when the document names the same person; if it names another parent (different first name or relationship), those are locked too ("The document names a different parent or guardian").
- Previous school and grade are added, with the date and document name, to the application's new **Document Details** field.
- Checks before saving: date of birth must be a real past date, emails valid, phone numbers at least 7 digits. Everything is saved in one transaction as the user.

## Measurement

The proposals are stored on the AI interaction as "Label: value" lines. On Apply, only the values staff **corrected** count as edits (unticked conflicts are decisions, not mistakes): Accepted when every applied value was used as read, otherwise Edited with the share of words changed. Discard records Rejected. Minutes saved per use: 6.

## Tests

`AiExtractionTest` (6 tests): proposals next to current values (pre-ticking, conflicts, normalisation, nulls skipped, comparable form stored); apply with a new guardian and school details (outcome Accepted); linked guardian vs a document naming another parent, and the same parent; validation (nothing ticked, unclear and future dates, invalid email and phone, guardian without last name) with nothing saved; text without letters and non-JSON answers refused; attached documents (text, PDF bytes, images refused). Jest: `kemAiDocumentReader` (5) and `kemPdfText` (2).
