# F3.6 — Retention workflows

**Status:** ✅ Built · ✅ Deployed · ✅ Unit tested · ✅ End-to-end checked (2026-10-06)

## At-risk scoring

The nightly **KEM Retention** job (04:05, `RetentionJob`, batches of 200) scores every Enrolled and On Hold enrolment from 0 to 100:

| Signal                                | Points                  |
| ------------------------------------- | ----------------------- |
| Attendance below the branch threshold | +30 (below 60%: +40)    |
| Last three marked sessions all absent | +25                     |
| An invoice of the enrolment overdue   | +15 (over 30 days: +25) |
| Course score below 65%                | +10 (below 50%: +20)    |

High is 50 or more, Medium 25 or more. Score, level, reasons and time are stored on the enrolment (`Risk_Score__c`, `Risk_Level__c`, `Risk_Reasons__c`, `Risk_Assessed_On__c`). When a learner **becomes** High (and is not already marked Leaving), the enrolment gets **Retention follow-up = Follow-up Needed** and a high-priority **task** on the learner for the branch manager (or the enrolment owner), due in two days. Re-scoring does not create a second task.

## Retention desk (`kemRetentionDesk`)

Home page (under the Cover Desk) and each Branch page, for administrators, branch managers and academic coordinators.

- Counts: high, medium, follow-up needed, retained; when the scores were last calculated; **Recalculate** for administrators.
- **At risk**: learners by score with reasons, follow-up status and the last note. **Log follow-up**: Contacted, Retained, Leaving or Follow-up needed with a note (required except for Retained); saved with who and when. Needs edit access to the enrolment.
- **Re-enrolment**: learners whose class ends within 30 days (or ended in the last 14) and who are not enrolled in a later class. Select learners → **Send invitations**: the fee payer receives the **Re_Enrolment_Invite** message (portal and email, consent rules of F2.5) and the invitation date is shown.
