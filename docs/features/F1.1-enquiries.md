# F1.1 — Enquiries: capture, assignment, follow-up, conversion

**Status:** ✅ Built · ✅ Deployed · ✅ Unit tested · ✅ End-to-end checked (2026-10-03)

## What it does

| Capability                      | How                                                                                                                                                                                                                                                                                                 |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Capture from staff              | Standard _New Lead_ with enquiry fields (branch, course/programme interest, channel, guardian details, learner birthdate)                                                                                                                                                                           |
| Capture from website / channels | `POST /services/apexrest/kem/v1/enquiries` (`EnquiryApi`), idempotent on `submissionId`                                                                                                                                                                                                             |
| Assignment                      | `EnquiryAssignmentService`: counsellor of the enquiry's branch (`Branch_Staff__c`, role _Admissions Counsellor_) with the fewest open enquiries; falls back to the branch manager                                                                                                                   |
| First follow-up                 | Enquiries with a branch get `Next_Follow_Up__c = now + 24h` and a high-priority _First contact_ task for the owner                                                                                                                                                                                  |
| Duplicate detection             | `EnquiryDuplicateService` flags matches on email/phone against open enquiries and existing people (`Possible_Duplicate__c`, `Duplicate_Details__c`); never blocks capture                                                                                                                           |
| Status lifecycle                | Governed by `Status_Transition__mdt` (New → Contacted → Nurturing → Qualified/Unqualified); _Unqualified_ needs a lost reason; _Qualified_ only through conversion                                                                                                                                  |
| Follow-up logging               | Workbench _Log follow-up_ creates a completed call task, stamps _Last Contacted_, schedules the next follow-up, and moves New → Contacted                                                                                                                                                           |
| Conversion                      | `EnquiryConversionService`: learner Person Account, guardian Person Account, Guardian↔Child `ContactContactRelation` (fee payer, emergency contact, portal access), admissions `IndividualApplication`, then standard lead conversion into the learner. Re-uses matching people; atomic (savepoint) |

## User interface

- **Admissions tab** (`kemEnquiryPipeline`): KPI header (open, overdue, due today, possible duplicates), branch filter, _My enquiries_ toggle, search, drag-and-drop between stages, per-card action menu (keyboard accessible alternative to drag-and-drop), convert and close actions.
- **Enquiry record page** (`KEM_Enquiry_Record_Page`, assigned in the Kasetti Education app): `kemEnquiryWorkbench` hero with stage path, duplicate banner, follow-up/learner/guardian/source tiles, _Log follow-up_, _Mark unqualified_, _Convert_.
- **Modals:** `kemEnquiryConvertModal` (choose existing/new learner and guardian, toggle application), `kemLostReasonModal`.

## REST API contract

```http
POST /services/apexrest/kem/v1/enquiries
Content-Type: application/json

{ "submissionId": "web-2026-000123", "branchCode": "DEMO-01",
  "firstName": "Ananya", "lastName": "Sharma", "email": "a@example.com", "phone": "+91...",
  "courseExternalId": "MATH-101", "channel": "Website", "deliveryMode": "Hybrid", "message": "...",
  "guardian": { "firstName": "Rohit", "lastName": "Sharma", "email": "...", "phone": "...", "relationship": "Father" } }
```

| Response                                              | Meaning                                                                                               |
| ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `201` `{enquiryId, created: true, possibleDuplicate}` | New enquiry                                                                                           |
| `200` `{enquiryId, created: false, ...}`              | Same `submissionId` seen before; enquiry updated, no duplicate created                                |
| `400` `{error}`                                       | Validation (missing `submissionId`/`lastName`/`branchCode`, unknown branch or course, malformed JSON) |
| `500` `{error: "... Reference: <request id>"}`        | Unexpected; details in `Error_Log__c`                                                                 |

The integration user needs `KEM_Admissions_Counsellor` + `KEM_Admissions_Counsellor_Edu` (or the persona group) to create enquiries.
