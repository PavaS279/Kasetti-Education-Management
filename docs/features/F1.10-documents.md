# F1.10 — Documents (offer letter, invoice, receipt)

**Status:** ✅ Built · ✅ Deployed · ✅ Unit tested · ✅ End-to-end checked (2026-10-03)

## What it does

| Capability           | How                                                                                                                                                                                                                                                                                                                                           |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Templates            | Visualforce `renderAs="pdf"` pages `KEM_Offer_Letter`, `KEM_Invoice_Pdf`, `KEM_Receipt_Pdf` with a shared header component (`KEM_Document_Header`): branded band with institution and branch address/contact, document number, A4 layout, page numbers                                                                                        |
| Data                 | `KemDocumentController` reads the record from the `id` parameter in **user mode** (only records the user can see). Offer letters show course, class, expiry and an indicative fee table from `PricingService`; invoices show bill-to, learner, dates, lines and totals; receipts show payer, method, reference, amount and how it was applied |
| Filing               | `DocumentService.generate(record, kind)` saves the PDF as a Salesforce File on the record (`ContentVersion.FirstPublishLocationId`), marked `KEM <kind>`                                                                                                                                                                                      |
| Preserved versions   | A document is generated **once** and then reused, so the copy that was sent never changes (later edits do not regenerate it)                                                                                                                                                                                                                  |
| Automatic generation | Offer made (`ApplicationService.decide` → Admit), invoice issued, payment confirmed → `DocumentService.Job` (queueable with callouts). Rendering counts as a callout, which is not allowed after uncommitted DML, so it runs after the transaction commits; failures are logged to `Error_Log__c`                                             |
| Guards               | Offer letter only once an offer exists; invoice PDF only for issued (not draft/cancelled) invoices; receipt only for confirmed payments; read access to the record is checked before filing                                                                                                                                                   |
| Institution name     | `Education_Setting__mdt` `Institution_Name` if set, otherwise the organisation name                                                                                                                                                                                                                                                           |

## User interface

**`kemDocuments`** on the application, invoice and payment record pages (new `KEM_Payment_Record_Page`, app override): lists the generated PDFs (title, kind, when, by whom) and one button — _Create …_ the first time, _Open …_ afterwards — which opens the Salesforce file preview (download/print/share from there).

## Tests

- Apex `DocumentServiceTest` (5 tests): invoice PDF created by the queued job after issue and never regenerated; receipt only after confirmation and reused; offer letter only after an offer; template controller data for all three pages (lines, totals, branch address/contact, indicative fees); unsupported and inaccessible records.
- Jest `kemDocuments`: create on first use, then list and open.
